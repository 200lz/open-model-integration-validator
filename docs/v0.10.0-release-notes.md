# OMIV v0.10.0 — Public Preview

`v0.10.0` is the first installable public-preview baseline for the Open Model
Integration Validator (OMIV). It is pre-1.0 Alpha software: public availability
does not imply production readiness, certification, safety approval, provider
endorsement, or complete model assurance.

## Status and installation

The repository is public and publicly readable, and `main` contains the audited release
candidate. The `v0.10.0` tag, GitHub Release, and PyPI project/version are not
yet created. Release preparation is therefore not release completion.

The current source-install path works before PyPI publication:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
omiv --version
```

After a separately authorized and independently verified PyPI publication, the
following command may become the primary quickstart:

```text
AVAILABLE_AFTER_VERIFIED_PYPI_PUBLICATION
python -m pip install open-model-integration-validator==0.10.0
```

## Included capability

The preview includes the Phase 5 trust, signature, attestation, governance,
security, runtime, and historical-evidence foundations; Phase 6A local payload
identity; Phase 6B remote snapshot/reconciliation; Phase 6C bounded quantization
fidelity; Phase 6D tokenizer/configuration parity; and Phase 6E runtime-resolution,
deployment-binding, supplied-backend, inference-identity, and output-provenance
reference semantics. The CLI and verifier are provider-neutral and offline-first.

These interfaces verify supplied, scoped evidence. They do not establish provider authenticity,
publisher authority, runtime-loaded weights without observation,
complete model equivalence, behavioral equivalence, safety, or production
readiness. Phase 6F Assurance Bundle interoperability is planned and unimplemented.
External artifacts may be explicitly unavailable; absence is not invalidity or
`PASS`. The known formatter-debt limitation remains recorded by the repository
quality gates.

## Reproducible release contract

The future release commit contains exactly one wheel, one source distribution, and one
deterministic `SHA256SUMS` file. The manifest uses lowercase SHA-256 digests,
lexicographically ordered filenames, two spaces between digest and filename, and
LF line endings. The exact bytes attached to the GitHub Pre-release must be the same
bytes later published to PyPI; the publishing workflow must not rebuild them.
The same bytes later published to PyPI are the only accepted artifact lineage.

The expected future tag is an annotated, cryptographically signed, immutable
`v0.10.0` tag with subject `OMIV v0.10.0 — Public Preview`. Historical `v0.1.0`
through `v0.9.0` tags are annotated but unsigned and retain that documented
limitation. A tag signature authenticates the tag under its selected key; it does
not certify model safety or evidence truth.

Current signing state is `RELEASE_SIGNING_KEY_NOT_CONFIGURED`; no private key is
loaded in this checkout. That blocks the later tag operation until an independently
reviewed release-signing key is configured and verified.

Verify future artifacts with:

```bash
sha256sum -c SHA256SUMS
python -m pip install --no-deps ./open_model_integration_validator-0.10.0-py3-none-any.whl
python -c 'import omiv; print(omiv.__version__)'
```

## Trusted publishing boundary

The future PyPI Trusted Publisher tuple is:

```text
owner: 200lz
repository: open-model-integration-validator
workflow: .github/workflows/publish-pypi.yml
environment: pypi
distribution: open-model-integration-validator
```

Current state is explicitly `PYPI_PROJECT_NOT_YET_CREATED`,
`TRUSTED_PUBLISHER_NOT_YET_CONFIGURED`, and `PYPI_VERSION_NOT_YET_PUBLISHED`.
No token or password is used. The owner must later verify the tuple, configure the
`pypi` environment, and separately authorize tag, GitHub Pre-release, and PyPI
publication operations. A duplicate PyPI version fails closed.

Release failures remain typed and fail closed:
`RELEASE_PREPARATION_COMPLETE`, `RELEASE_SIGNING_KEY_NOT_CONFIGURED`,
`TRUSTED_PUBLISHER_NOT_CONFIGURED`, `SIGNED_TAG_CREATION_FAILED`, `TAG_PUSH_FAILED`,
`GITHUB_DRAFT_RELEASE_FAILED`, `GITHUB_PRERELEASE_PUBLICATION_FAILED`,
`RELEASE_ASSET_IDENTITY_MISMATCH`, `PYPI_TRUSTED_PUBLISHING_FAILED`,
`PYPI_VERSION_ALREADY_EXISTS`, `PYPI_HASH_MISMATCH`, `PYPI_METADATA_MISMATCH`,
`POST_PUBLICATION_INSTALL_FAILED`, `PARTIAL_RELEASE_REQUIRES_MANUAL_REMEDIATION`,
and `RELEASE_COMPLETE`. A GitHub Release does not prove PyPI publication; exact
artifact hashes must bind both surfaces. No failure is hidden with `skip-existing`.

## Security and roadmap

Report vulnerabilities through [SECURITY.md](../SECURITY.md), never through a
public issue containing sensitive details. See the [architecture](architecture.md),
[quickstart](quickstart.md), [changelog](../CHANGELOG.md), and
[roadmap](roadmap.md). The roadmap remains:

Bundle core → Phase 6 Final Integration Audit → `v0.11.0` Public Preview →
DeepSeek Artifact Case Study → Meta Muse Artifact Case when official assets are
stable → Preflight/adoption UX → Phase 7 enterprise operational layer.

DeepSeek and Meta Muse validation are not complete, and no provider affiliation or
commercial service is claimed.
