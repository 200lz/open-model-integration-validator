The immutable `v0.10.0` annotated tag targets
`09f8265d62f2ea1dfda7da2cd3eb4b3e89639222`, and its tag object is
`d26468e050f4f0aea11e1d1631c92e1e1fbb7bcc`. The published GitHub pre-release

Run `31556942770` failed in `git verify-tag v0.10.0` with `Can't check signature:
No public key`; the publish job was skipped. The root cause is classified
`TAG_SIGNATURE_PUBLIC_KEY_BOOTSTRAP_MISSING`. Rerunning attempt 1 cannot repair it:
the release event is bound to the old tagged workflow and repeats the same missing-key
logic. The signed tag must not be changed, and the GitHub Release must not be deleted
or replaced. Manual upload, API-token fallback, and `skip-existing` are prohibited.

## Manual recovery contract

The existing `release: {types: [published]}` trigger remains. `workflow_dispatch`
adds one required string input, `tag`. Verification fails closed unless the strict
semantic tag is the reviewed release, the remote and local annotated-tag objects,
subject, target, exact `VALIDSIG` signing subkey, and primary fingerprint agree, the
existing Release is published, non-draft, and prerelease, and its only assets are the
reviewed wheel, sdist, and deterministic `SHA256SUMS`. PyPI must return 404 before the
first upload.

The package source is checked out explicitly from `refs/tags/<tag>`; dispatch branch
HEAD is never package source. The publish job re-downloads the existing Release assets,
revalidates their manifest and digests, and passes only those bytes to the immutable
full-SHA-pinned official PyPI action with attestations enabled. Only that job has
`id-token: write`, and it uses environment `pypi`.

Future recovery dispatches must use a signed tag ref containing this workflow. The
current `v0.10.0` tag predates `workflow_dispatch`, so recovery of this one version
requires a separate, temporary, explicitly authorized `main` deployment-policy
exception. The current environment remains tag-`v*` only; this correction neither
changes that policy nor performs a dispatch or publication.

Each future version requires a reviewed, exact release contract in the workflow
revision included by its signed tag. An unknown tag is rejected rather than inferred
from branch state or mutable assets.

This provenance chain attests the publication mechanism and exact subjects. It does
not establish model-artifact authenticity, software safety, compliance, or production
readiness. Phase 6F and Phase 7 remain unimplemented.
